# PROTOCOL_HW_MB, Amendment 3: revision-3 K = 2 image with runtime n (all G-set sizes)

Frozen on 8 October 2026, before any revision-3 board data. At freezing time the revision-3 image (`board_mb2n_e12_250mhz`) is still being built, and the board holds the v6.4 headline image. Hashes are in `PROTOCOL_HW_MB_A3.sha256`. `PROTOCOL_HW_MB.md` and Amendments 1 and 2 are unchanged.

## Why

- The paper needs measured K = 2 G-set results for all three graph classes: random, toroidal and planar. Two classes need N = 800 or 1000 instances (G1–G21, G43–G47, G51–G54).
- The revision-1 image has the active spin count fixed at N = 2000 when it is built.
- Revision 3 (`src/v6/sca_core_mb_r3.v`) makes n a runtime header field. The semantics are those of the shared golden model `src/sca_ref_bias.hpp` `run_trial_bias`:
  - spins i ≥ n are padding and are never updated;
  - padding spins do not count in n_lin or in flips;
  - padding spins read out as 0;
  - the random-number streams are consumed exactly as in `run_trial`.
- Revision 3 also carries the cut-word fix from revision 2 (Amendment 2).
- The image is built with the per-spin bias option off (`BIAS = 0`). Its cycle behaviour is that of revisions 1 and 2.
- The revision-2 build was stopped during routing, superseded by revision 3. It was never programmed.

## Image and software

- **Core.** `src/v6/sca_core_mb_r3.v` with K = 2, BIAS = 0 and HB = 12.
- **Front end.** `src/v6/sca_mover_mb3.cpp`, variant `mb2n`. HLS C simulation and C/RTL co-simulation both PASS, including header cases with n and the bias flag.
- **Build.** 12 engines at 250 MHz, with the pblocks, register slices and post-route optimisation of `board_mb2_e12_250mhz`.
- **Host.** `src/host_sca_multi_mb3.cpp` with `src/mb_common3.hpp`. On every launch it writes n = the problem's N into `load_J` bits 27..16. Every result is rescored independently from the spins. It also checks that output bits of spins ≥ n are 0.
- **Simulation sign-off before the build (xsim, all PASS, bit-exact against `run_trial_bias`).** All runs are in `build/sim_mb3_20261008b`:
  - K2000 short suite with n = 2000 written explicitly, and with n = 0 (build-time default);
  - K2000 O4 and X5;
  - G22 negative-score suite;
  - G1, G11 and G14 (N = 800) short suites;
  - one traced trial of each study rule's E12 configuration on G1, G11, G14 (N = 800) and G43, G51 (N = 1000).

## Procedure (`scripts/bringup_mb3.sh`, unattended)

1. **Preconditions.** Wait for the pipeline. Require pipeline status 0 and timing PASS. Check this amendment's hashes. If any check fails, the board is left untouched with v6.4 programmed.
2. **Program the image.** Back up the staged PDI and record its SHA-256. Program `board_mb2n_e12_250mhz` with the scoped command.
3. **Run the amendment** (`scripts/run_hw_mb3.sh`), seed 20261004, tables resident, 12 engines:
   - **Phase 1, exact gate.** Every trial is verified bit for bit against `run_trial_bias`: spins, score word, flips and n_lin trace. The sets are:
     - K2000 W1–W4, with the trial ids of PROTOCOL_HW_V6;
     - G22a/b and G32a/b from the main protocol;
     - G22neg_plain and G22neg_ons from Amendment 2;
     - one set per instance for all 51 instances (`PROTOCOL_HW_MB_A3_verify.txt`): the instance's original Onsager-online E12 configuration, 12 trials, trial ids 950000 + 100·index.
   - **Phase 2, K2000 regression.** X5 and O4 with 2052 trials each, trial ids 0–2051, one trial per launch. These are the configuration strings and launch shape of the v6.4 12-engine run.
   - **Phase 3, G-set.** `PROTOCOL_HW_MB_A3_gset.txt` was generated by `scripts/gset_amend_mb3.py` from the study file `selected_configs.json` (SHA-256 291401004efe27e4…) with no other input. It covers:
     - the study's `tts_E12` selection for each of the four rules the engine implements (plain SCA, TEC, Onsager-kT, Onsager-online), in both grid variants, with identical configurations run once;
     - 264 cohorts: 120 for N = 800, 44 for N = 1000 and 100 for N = 2000;
     - 6156 trials per cohort (513 rounds of 12 engines), trial ids 0–6155.

     The N = 2000 cohorts use exactly Amendment 1's keys, arguments, seed and trial ids 0–2051.
   - **Target.** The study's target, which is 99% of the best-known value.
4. **Power.** `scripts/measure_power_mb3.sh` with `PROTOCOL_HW_MB_A3_power.txt`: 150 s of back-to-back load per configuration and 60 s idle between loads, sampled from hwmon4. The configurations are:
   - X5, G22_ons and G32_tecT, as in the main protocol;
   - the study's original Onsager-online E12 configurations for G1 (N = 800) and G43 (N = 1000).
5. **Restore and analyse.** Restore the v6.4 headline image with the scoped command, regardless of the outcome. Then run `scripts/analyze_hw_mb_a3.py`, followed by `scripts/analyze_power_mb.py`.

## Predictions (pass conditions)

| ID | Prediction | Pass condition |
|---|---|---|
| A3-E | Exact on every set and every size | Every trial in every set is bit-exact, padding bits are 0, and every set covers all 12 engines |
| A3-R | K2000 identical to v6.4 | X5 and O4: the same cut and flips per trial id as the v6.4 12-engine run (2052 of 2052 each); W1–W4 identical to v6.4's sets |
| A3-C | Same cycle behaviour as v6.4 | Launch-cycle ratio against v6.4 within 1% (X5, O4) |
| A3-I | Revision 3 at n = 2000 equals revision 1 | All 100 N = 2000 cohorts: trial ids 0–2051 have the same cut and flips as Amendment 1 on the revision-1 image |
| A3-P | The engine reproduces the study's success probabilities | Per cohort: \|p_board − p_study\| ≤ 1.96·sqrt(p̄(1 − p̄)(1/n_b + 1/1024)) + 0.02. Pass if at least 90% of the 264 cohorts satisfy it |
| A3-T | Measured time against the study's estimate | Median over cohorts of (board primary TTS99) / (study `tts_E12`) within [0.8, 1.5] |

**TTS estimators.** These are those of `analyze_hw_mb.py`. The primary TTS99 is t_R·ln(0.01)/ln(1 − P_round), where:
- P_round is the fraction of 12-engine rounds with at least one success;
- t_R is the mean device time of rounds after round 0.

## Reporting

- **Best TTS99 per instance.** Reported across rules and both variants. This is a post-hoc minimum and is labelled as such.
- **Geometric means.** Reported per rule over the original-variant cohorts, and per class:
  - random: G1–G10, G22–G31, G43–G47;
  - toroidal: G11–G13, G32–G34;
  - planar: G14–G21, G35–G42, G51–G54.
- **Board power.** Board power and energy to solution per load.
- **Failed predictions.** Any failed prediction is reported as failed. Nothing is re-run under the same label.

## Limits

- The engine always sweeps 2048 spin slots, so an N = 800 step costs the same cycles as an N = 2000 step with the same flips.
- The study's p values come from its float model with n = 1024 per configuration, while the board runs the engine's fixed-point arithmetic. The 0.02 margin in A3-P covers this, as in Amendment 1.
- Revision 3 was not separately validated against the revision-1 board results before this amendment. A3-I is that check.

# PROTOCOL_HW_MB, Amendment 1: the G-set study's 12-engine selections

Frozen on 7 October 2026 at 18:16 UTC. This is before any multi-bit board data: the multi-bit image was not yet built or programmed, and the board still held v6.4. Hashes are in `PROTOCOL_HW_MB_A1.sha256`. `PROTOCOL_HW_MB.md` and its frozen files are unchanged and run first, exactly as frozen.

## Why

- The software G-set study's selection (`research/gset_20261007/selected_configs.json`, SHA-256 291401004efe27e4…) arrived at 18:03 UTC. That was after the main protocol was frozen (15:55 UTC) with pre-declared contingency configurations.
- The original plan asks for G-set TTS99 at 99% of best-known for the instances the study selects. This amendment adds those configurations. Nothing in the main protocol is changed or removed.
- **Operational note.** The unattended bring-up launched at 15:55 UTC was stopped at 18:11 UTC, while it was still waiting for the build and before any board action. It is relaunched through `scripts/bringup_mb2_a1.sh`. That script runs the frozen `scripts/bringup_mb2.sh` unchanged, with `RESTORE_V64=0`, then this amendment, then restores the v6.4 headline image.

## What

**Instances.** All 21 instances with N = 2000, the engine's N: G22–G42. Raw files are from the Stanford G-set page, with SHA-256 values in `data/gset/SHA256SUMS.all` (local copy `results/multibit_20261007/data/`).

**Rules.** The engine implements four of the study's rules, and the mapping is exact:
- plain SCA;
- TEC, `--tec-jv`;
- Onsager-kT, which is `--tecT κ --ramp`;
- Onsager-online, `--lambda λ --ramp`.

All use correction scale 1, because the study's λ already includes the d̄/N factor and κ is in absolute units. APC-SCA has no 12-engine selection and is not implemented in the engine.

**Configurations.** The study's `tts_E12` selection for each rule, in both grid variants: `original` (pre-registered) and `extended_amendment1`. Where the two variants coincide, one cohort is run and both labels are attached.
- That gives 100 cohorts (68 shared by both variants, 32 variant-specific), with S ∈ {250, 500, 1000, 2000, 4000}.
- Each cohort has 2,052 trials: 171 rounds of 12 engines, trial ids 0–2051, seed 20261004, one trial per launch, tables resident.
- The list is `PROTOCOL_HW_MB_A1_gset.txt`, generated by `scripts/gset_amend_mb.py` from the study file with no other input.

**Exact gate.** One set per instance (`PROTOCOL_HW_MB_A1_verify.txt`): the instance's original Onsager-online E12 configuration, 12 trials, trial ids 930000 + 100·i.

**Run and analysis.**
- `scripts/run_hw_mb_a1.sh` runs on the same image after the main protocol and power phases.
- Analysis: `scripts/analyze_hw_mb_a1.py <results/hwmb_board_..._a1> PROTOCOL_HW_MB_A1_predictions.json`. It uses the same TTS estimators as the main protocol: primary over rounds, round 0 excluded.

## Predictions (pass conditions)

| ID | Prediction | Pass condition |
|---|---|---|
| A1-E | Exact on every instance | All 21 × 12 exact-gate trials bit-exact with `sca_ref.hpp` `run_trial(..., dense)` |
| A1-P | The engine reproduces the study's success probabilities | Per cohort: \|p_board − p_study\| ≤ 1.96 · sqrt(p̄(1 − p̄)(1/2052 + 1/1024)) + 0.02. The 0.02 allows for the study's float model against the engine's fixed-point arithmetic and 16-bit uniforms. Pass if at least 90% of the 100 cohorts satisfy it |
| A1-T | Measured 12-engine time against the study's estimate | Median over cohorts of (board primary TTS99) / (study `tts_E12`) within [0.8, 1.5] |

- **Why A1-T is not centred on 1.** The study's time is a model. At low flip rates the engine has a per-step floor of about 22.6 cycles, and the board adds launch overhead. So ratios above 1 are expected for short, sparse schedules.
- **Reporting.** The best measured 12-engine TTS99 per instance is reported across all rules and both variants. This is a post-hoc minimum and is labelled as such.

## Limits

- The study's p values come from its float model with n = 1024 per configuration; the board runs the engine's fixed-point arithmetic.
- G1–G21 and G43–G54 are not run, because N ≠ 2000.
- The main protocol's contingency G22/G32 configurations remain the pre-registered primary G-set result. This amendment is reported separately and is never pooled with them.
